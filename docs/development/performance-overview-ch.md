## 二、现在的编译与渲染性能测试总览

### 测量条件与覆盖

Node v22.17.0，Intel(R) Core(TM) Ultra 5 125H，Windows x64。Node 压力场景使用独立进程和 1 GiB 老生代上限；浏览器为 Edge 135.0.3179.66 无头模式、1440×1000 视口。机器上保留日常开发进程，未固定电源策略或 CPU 频率。各性能脚本串行运行。

通常预热 3 次、测量 15 次，长行和超预算专用用例分别为 5/3 次，独立浏览器 Worker 为 2 次预热、5 次测量；具体以摘要数据为准。P95 使用最近秩，15 样本时等于最大样本，只用于观察尾部。首次调用、公开快照复制、共享 Worker 结果与主线程渲染分别记录。

RSS 是进程高水位，包含 Node、模块、输入及临时对象；GC 后堆是保留量，二者不能互换。JSON UTF-8 消息体积是估算，结构化克隆成本另测。输入到预览终点为提交后的两次 requestAnimationFrame 帧机会；CDP Paint 是绘制阶段事件，均不代表 GPU 完成显示。不同 React 阶段有重叠，不能相加。

500 层引用块在这批 Node 测量中略慢；深层工作的主要收益是减少组件正文的重复解析、提前终止超限输入，以及消除浏览器调用栈和结果传输失败。1000 层列表仍需数百毫秒，通用容器解析仍有优化空间。

真实 Edge module Worker 通过 100/500/1000 层引用块、1000 层列表及 500 组引用/列表混合嵌套，深层编辑后的叶表达式正确。损坏扁平帧只恢复一次完整请求，随后 1001 层预算拒绝及普通文档恢复正常。CM6 与 React 预览通过 500/1000 层引用、1000 层无序/有序列表及混合嵌套；原有 DOM 层数保留，表达式从 `n * 2` 编辑为 `n * 3` 后显示 39，参数保持 13，仅创建一个 Worker，页面及控制台错误为空。

实现包含三项约束：快速计划每次校验当前解析产生的占位符位置和类型，首遍表达式屏蔽计划只提供 Markdown 事实，禁止生成正文节点；深结果通过 `flatResults: "flat-v1"` 协商为扁平记录与引用，普通文档继续使用现有补丁；32 层以上的单子 Markdown 容器链迭代构造原生包装，减少 React memo 组件层数，保留 native DOM 结构。6000 层数据复制、共享、扁平编码/解码、运行时索引和视图投影另有单元验证。

1000 项动态列表连续编辑 500 次：第 50–500 次 GC 后堆增长 0.463 MiB，保留堆 18.146 MiB，释放会话后 13.095 MiB；解析缓存最终 524 项，仍在 672 项上限内。

实现参考 [Lezer 的上下文与增量复用约束](https://lezer.codemirror.net/docs/guide/) 和 [V8 的迭代遍历方案](https://v8.dev/blog/json-stringify)。扁平记录参考 [@ungap/structured-clone 的对象索引表](https://github.com/ungap/structured-clone/blob/main/esm/serialize.js)；该实现的访问函数仍递归，本轮针对编译器普通数据自行实现迭代遍历，无新增依赖。

本轮门禁：116 个核心测试文件、1534 项测试和 16 个 Demo 文件、254 项测试通过；类型检查、生产/standalone/声明构建、Demo 构建、公开包检查及离线打包消费通过；文档链接和 `git diff --check` 通过。深层压力单元测试单独设置 30 秒超时，性能统计由生产包脚本承担。

### 当前边界与后续优化位置

- 5000 个普通短段落的公开快照路径中，会话编辑为 64.33 ms，慢于完整编译的 44.59 ms。共享和完整快照发布仍有全树成本，应分别优化公开快照与 Worker 私有共享路径。
- 上一轮完整矩阵曾出现动态表格和列表的尾部回退。本轮浏览器对照改善了中位数和 P95，但 Node 移位列表仍有批次回退，需要继续追踪分配和 GC 对尾部的影响。
- 简单动态插值行已进入快速路径。包含链接、转义或复杂行内格式的动态块仍可回退；下一步可研究行片段解析和语义汇总的局部更新，继续用全量结果差分验证。
- 大列表/表格移位编辑要重定位大量范围；全块重写的补丁编码和成本估算仍可能提高 Worker 时间，应先减少编码前的重复遍历。
- CM6 仍通过完整源码字符串与宿主同步，作者分析也会生成整份结果；长单行、超长字符串和大型依赖图仍有线性工作。
- 预览适合继续做行/块级订阅与按视口延迟可视化。真正卸载离屏预览前，需要保留状态、锚点、原生查找、跨块选择和打印。
- 默认深度预算仍为 Markdown 1000 层、组件 100 层。深结果通过公开调度器协商 `flat-v1` 后传输；直接把深层 `compileLocal()` 结果交给原生 `postMessage()` 的自定义 Worker 仍受浏览器调用栈限制。深层结果目前每次传完整扁平快照，后续可研究子树补丁。物理中文输入法、移动键盘和辅助技术需要目标设备人工验收。
