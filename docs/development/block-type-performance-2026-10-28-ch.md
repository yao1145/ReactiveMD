# 不同块类型的编译性能测试

本文记录首次块级增量实现的基线。后续对连续上下文修改、列表和表格的优化及前后对比，见[上下文缓存、列表与表格优化](context-table-optimization-2026-10-28-ch.md)。

2026-10-28，ReactiveMD 0.6.1 当前工作区，构建后测试 24 个场景。普通段落、标题、引用、代码、常见格式和表达式块在长文中的编辑中位数约为 4–16 ms；大表格更贵。组件内部修改触发完整编译，部分场景还承担缓存重建开销。

## 测量方法

- Windows x64、Intel Core Ultra 5 125H、Node 22.17.0，默认 V8 堆；机器同时运行其他开发进程。
- 每个场景独立 Node 进程，串行执行，预热 3 次、测量 21 次，报告中位数和最近秩 P95。原始样本全部保留，未剔除长尾。
- 同一场景内单块与长文测试共享模块缓存，结果表示预热后的编译成本。
- 单块成本调用公开的 `compileLocal()`。表达式段落和 Plot 同时带一个必要的 slider 声明，其节点数和耗时包含该声明。
- 长文由相同的 1,000 个普通背景段落和居中的目标块组成；普通背景约 75,000 字符、2,000 节点。每次将目标中的版本号换成另一个四位数，保持源码长度和后续偏移不变。围栏定界符场景单独改变开、闭围栏长度。
- 完整编译与会话编译交替先后顺序。计时包含完整结果组装，源码生成、断言和最终结构对照在计时外。各场景最后一份会话结果在规范化节点 ID 后与完整编译逐字段一致；全部结果成功且没有诊断。
- 公式包含编译阶段的显示兼容检查。代码高亮、曲线采样、图表渲染、ELK 布局、React、浏览器布局与绘制均未计入。这里测量 Node 编译，未测 Worker 传输。

块尺寸和节点数不同，应结合下表解读类型成本。单块数字包含整个公开编译 API 的成本，不能理解成纯词法分析时间。会话数字是已有缓存后的编辑成本，首次建立会话另有开销，记录在 JSON 的 `initialSessionMs`。

## 独立复测

对 200×4 表格、Panel 内部修改和柱状图数据修改再次启动独立进程，保持 3 次预热、21 次测量。

| 场景 | 完整中位数 | 会话中位数 | 会话 P95 | 模式 |
| --- | ---: | ---: | ---: | --- |
| Markdown 表格，200×4 | 100.16 | 39.14 | 187.12 | incremental |
| Panel 内部，50 段 | 181.13 | 222.21 | 702.65 | full |
| 柱状图数据，20 行 | 117.95 | 131.90 | 232.70 | full |

200×4 表格两轮会话中位数为 55.55 / 39.14 ms，P95 为 130.15 / 187.12 ms，长尾明显。Panel 两轮会话相对完整编译分别额外耗时约 46% / 23%；柱状图约 42% / 12%。两轮都确认这两类修改未命中块级增量。具体毫秒值随调度和 GC 波动，应保留这一区别。

## 结果解释

1. 普通段落和标题的单块成本较低。511 字符与 8,191 字符普通段落的长文会话中位数都在约 4 ms，表明源码差异扫描、快照组装等背景工作已占据主要部分；较大段落在本轮略快属于观测波动。
2. 节点密度影响明显。6,390 字符围栏代码只有 1 个输出节点，长文编辑约 7.00 ms；5,610 字符的 200×4 表格有 1,810 个节点，本轮约 55.55 ms。列表和表格会重新编译整个列表/表格，当前没有单项或单行级复用。
3. 表格规模上升会增加块内解析和对象处理成本。20 / 100 / 200 行表格的单块中位数分别为 3.69 / 15.67 / 23.04 ms，长文会话为 9.08 / 20.56 / 55.55 ms。
4. 显示公式和插值可以局部编译。20 / 80 项公式的单块中位数为 2.96 / 5.71 ms，长文会话为 6.71 / 11.45 ms；20 个响应式插值为 7.93 ms。公式显示检查仍有自身成本。
5. 文档中的语法会影响完整编译路径。纯普通文本可走直接解析，加入格式、数学或组件后需要通用解析流程，所以同样背景下完整编译耗时并不固定。增量缓存能保留这些未变化的背景块。
6. 当前组件编辑仍有明确缺口。滑块初值、Panel 内文、ReactiveMD 表格、Chart、Plot 和 Diagram 内容变化都会使上下文失效。会话执行完整编译后再次提取缓存、建立语法索引并编译声明前缀，可能比直接 `compileLocal()` 更慢。围栏定界符修改也有类似开销。源代码路径见 `LocalCompileSession.compile()` 的完整编译与 `seed()` 分支。

后续优化应优先处理连续上下文修改时的缓存重建开销，并评估组件内部的增量单元；大列表和表格则适合进一步研究单项、单行或子树复用。以上测试保留当前实现，未调整这些回退策略。

## 复现与原始数据

```sh
npm run build
node scripts/benchmark-block-types.mjs --output artifacts/benchmark-block-types.json
node scripts/benchmark-block-types.mjs --case '^(panel-50|chart-20|table-200)$' --output artifacts/benchmark-block-types-confirm.json
```

支持 `--iterations`、`--warmups`、`--background`、`--case` 和 `--output`。快速检查可用 `--iterations 1 --warmups 0 --background 12`；它没有足够预热，不能代替正式时间数据。
