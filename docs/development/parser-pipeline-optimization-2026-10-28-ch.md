# 解析流水线优化：分段映射、块级分流与直接节点生成

2026-10-28。基线为 `fb05509`，接续[上下文缓存与表格优化](context-table-optimization-2026-10-28-ch.md)。本轮完成讨论中的解析层基础改造，公开编译结果和现有预算语义保持一致。

## 已实现的路径

`SourceContext` 为 parser/compiler 提供同一份 LF 行起点索引，保留现有诊断行列语义。CR-only 的逻辑行数按需计算。去缩进按行追加源码片段，行定位使用索引，替代原先每个字符调用 `lastIndexOf()` 的处理。

`MappedSource` 用连续源码段和固定位置的生成段表示映射。连续源码段按偏移平移，生成占位符映射到相同的原始位置；去缩进产生的新起点开启新段。相邻兼容段合并，查询使用二分与最近段缓存，区域终点单独保存。`convert()` 和组件内的脚注、数学字面量发现均已接入。

`planFastMarkdown()` 先验证简单语法并精确计数，再直接调用节点工厂生成 `LocalNode`。生产路径不再构造完整的 `FastNode` 树。超预算时按原后序构造顺序定位第一个被拒绝的节点；完整简单文档可以在生成任何 ReactiveMD 节点之前返回相同的预算诊断。旧 `parseFastMarkdown()` 保留为兼容入口。

`parseMarkdownBlocks()` 先尝试整篇简单计划，失败后使用 Lezer 的顶层范围提出候选，再逐块验证。已确认的块被等长空白遮蔽，剩余内容一次交给 remark，保留引用定义和脚注的文档环境。通用节点与候选重叠、脚注懒续行等边界不一致时回到原路径。快速计划也用于前置屏蔽阶段，减少中间节点。CR-only 只在候选解析的视图中等长转换，真实源码和位置保持不变。

纯词法占位符和空白组成的转换结果直接进入通用解析，跳过不会产生快速块的候选树构造，避免大量组件承担额外扫描。

## 正确性边界

- 简单块确认成功后才提交节点；识别失败不消耗 ID 或预算。
- 行内链接、转义、引用定义、脚注、代码、HTML、组件及复杂列表继续由原通用规则决定语义。
- 位置按原始 UTF-16 代码单元计算，保留 BOM、LF/CR/CRLF、缩进和占位符端点映射。
- 使用精确节点计数提前拒绝，未增加任意行数、块数或 Markdown 深度硬限制。通用 remark 内部的所有临时分配尚未纳入统一工作预算。

## 生产包对照

Windows x64、Intel Core Ultra 5 125H、Node 22.17.0、默认 V8 堆。基线完整生产包保存在本地忽略目录。每个场景独立子进程串行运行，版本先后顺序按场景交替；默认预热 3 次、测量 15 次。长行测量 5 次，超预算列表 3 次。计时包含完整结果生成，排除源码生成、断言、哈希和显式 GC。结果比较对完整公开对象排序后计算哈希，不忽略节点 ID 或诊断位置。

| 场景 | 优化前中位数 | 优化后中位数 | 优化前 / 后 P95 | 峰值 RSS：前 / 后 |
| --- | ---: | ---: | ---: | ---: |
| 80 块混合列表、表格与一个链接/转义块 | 82.21 ms | 39.61 ms | 127.84 / 50.52 ms | 204.29 / 156.85 MiB |
| 1000×4 普通表格 | 53.21 ms | 48.78 ms | 79.25 / 70.57 ms | 177.59 / 171.29 MiB |
| 500×4 ReactiveMD 表格 | 72.79 ms | 33.46 ms | 111.00 / 39.92 ms | 201.59 / 150.42 MiB |
| 容器内 16k 缩进长行 | 51.54 ms | 5.04 ms | 67.94 / 5.73 ms | 93.13 / 70.91 MiB |
| 容器内 64k 缩进长行 | 662.03 ms | 6.31 ms | 665.04 / 21.97 ms | 177.75 / 68.47 MiB |
| 容器内 256k 缩进长行 | 9846.93 ms | 25.09 ms | 10168.90 / 27.88 ms | 196.63 / 70.25 MiB |
| 50,000 项列表，按原预算拒绝 | 57.62 ms | 16.25 ms | 100.73 / 26.20 ms | 246.76 / 114.43 MiB |

大长行的主要收益来自消除逐字符回查行首。长行从 16k 增长到 64k 时，旧版耗时约增加 13 倍；新版不再出现同样的增长。RSS 是整个子进程的最高常驻内存，包含加载、预热、多轮编译和结果哈希，不能等同单次解析额外内存。

## 补测与观测

混合块独立补测预热 10 次、测量 51 次，中位数为 82.66 → 32.97 ms，P95 为 127.91 → 45.76 ms。

首轮普通段落出现小幅回退，因此将 CR 逻辑行数改为按需统计。最终 1000 段普通文本预热 10 次、测量 101 次，中位数 10.35 → 9.22 ms，P95 为 17.56 → 17.35 ms。上表保留首次完整对照，普通段落采用修正后的独立报告。

包含 500 行插值的组件表格继续使用通用表格解析，7 次样本中位数 81.22 → 73.78 ms，P95 为 124.41 → 113.93 ms。它主要受益于映射与去缩进改造。

5000 个组件的补测发现纯占位符仍承担候选扫描，因此增加了跳过规则。最终预热 5 次、测量 15 次，中位数为 525.83 → 525.59 ms，基本持平；P95 为 643.40 → 689.40 ms，峰值 RSS 为 528.70 → 536.43 MiB。本轮未改善该场景的尾部耗时与内存峰值。

内部 `ParsedLocal.work` 记录解析调用数、快速/通用块数、对应源码范围、映射段数、源码 LF 行数和组件深度，不进入公开文档。80 块混合文档中，79 块使用快速计划，仅 1 块走通用节点生成。未遮蔽范围为 196 个代码单元，包含空白；remark 仍读取整篇等长的遮蔽文本。256k 长行所有相关转换累计仅使用 6 个映射段。

工作量统计会累计嵌套和屏蔽调用，同一源码可能计入多次，表示实际经过的解析工作，不表示文档的唯一覆盖率。
