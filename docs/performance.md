# 性能测量

在源码仓库根目录构建语言包，然后运行：

```sh
npm run build
npm run benchmark
```

脚本对每个场景预热 3 次、测量 20 次，报告中位数和 P95，原始结果写入 `artifacts/benchmark.json`。可用 `npm run benchmark -- --iterations 50 --output artifacts/benchmark-50.json` 改变次数和输出位置。报告包含包版本、Node 版本、操作系统和 CPU 信息。

## 本地基线

2026-10-22，Reactive MD 0.3.0，Node 22.17.0，Windows x64，Intel Core Ultra 5 125H。测量时机器上也有其他开发进程运行。

| 场景 | 中位数 | P95 |
| --- | ---: | ---: |
| 编译费用示例，378 字符 | 2.51 ms | 5.83 ms |
| 编译 250 行响应式表格，7,161 字符 | 17.04 ms | 28.05 ms |
| 编译 100 节文章，15,550 字符 | 45.34 ms | 59.81 ms |
| 连续 100 次状态写入与表达式求值 | 0.20 ms | 0.34 ms |
| 三条曲线，每条 200 个采样点 | 0.55 ms | 1.61 ms |

计时包含正确性断言，运行时场景的一次测量包含 100 次更新。绘图场景包含正常函数与非网格渐近线的断点检查。

这些数据测量 Node 中的编译、求值和采样，不包含浏览器排版、绘制或输入到画面的延迟。数值用于同条件下比较版本，不设置跨机器通过阈值，也不代表源码上限内的所有文档都有相同耗时。CI 保存 Node 24 的测量报告；[首轮 CI](https://github.com/yao1145/ReactiveMD/actions/runs/39782886373) 已通过并生成报告。

## 宿主中的大文档

文档源码上限为 1,000,000 个 UTF-16 代码单元，绘图和表达式还有独立计算预算，详见[安全策略](../SECURITY.md)。资源上限控制工作量，编译 API 仍是同步调用。编辑器可以合并连续输入触发的编译；处理来源不可信或较大的文档时，可以在宿主 Worker 或独立进程中编译，并由宿主控制并发和超时。
