# 弃用与迁移政策

**中文** · [English](deprecation-en.md)

本政策从 `reactive-md@0.9.2` 和 `reactive-md-editor@0.2.1` 生效，适用于[稳定公共 API](api-stability-ch.md)。两包独立计版本和弃用周期。

## 公告、保留与移除

1. 在版本变更记录和相应 API 文档中公告弃用。记录受影响的入口或符号、首次公告版本、建议替代项、最早移除版本，以及可执行的迁移步骤。可标记的 TypeScript 声明加上 `@deprecated`，并指向替代项。
2. 保留旧接口至少 90 天，并覆盖首次公告之后完整的一个 minor 发布线。旧接口继续在同一 minor 的补丁中接受兼容性和安全修复。
3. 两项保留条件均满足后，在后续的次版本或主版本移除，并在变更记录中确认移除版本和迁移方式。例如，在 `0.9.x` 公告的弃用应覆盖 `0.10.x`，最早在公告满 90 天后的 `0.11.0` 移除。

安全漏洞、数据损坏或外部平台强制变更需要缩短保留期时，在发布记录说明原因、影响范围和可用的回退或迁移路径。安全问题可以在修复发布时披露。0.x 次版本中的其它不兼容改动也须公开列出旧用法、新用法和适用版本。

## 当前宿主迁移

编辑器 `0.2.1` 的最低引擎版本为 `0.9.2`，peer 范围为 `^0.9.2`。已有安装可以成对升级，或在引擎 `0.9.0`、`0.9.1` 上继续使用编辑器 `0.2.0`。这是本次候选公开记录的配对要求变更。现有编辑器入口和组件导入仍可使用。

公开的 `LocalComponentPropValue` 是早期标量类型别名，已在声明中标记弃用。新的扩展应使用 `LocalComponentValue`，需要标量时先缩窄类型。该别名的保留期从本政策首次记录的发布开始计算。

源码迁移独立于宿主 API 弃用。跨语法修订时，先使用 [源码修订和迁移工具](source-versioning-ch.md) 检查源码。迁移后的源码应重新导出状态文件，以更新源码摘要。引擎 `0.9.2` 继续使用 `local-draft-3` 与 `reactive-md-state/v1`。
