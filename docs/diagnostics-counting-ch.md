# 诊断与计数规则

[English](diagnostics-counting-en.md)

本页定义 0.4.x 的诊断契约、字符长度单位与资源预算作用域。

## 诊断契约

`Diagnostic` 的机器字段为 `code`、`severity`、`range`、`line` 和 `column`。`message` 是默认英文显示文本。宿主使用 `formatLocalDiagnostic(diagnostic, 'zh')` 或 `'en'` 取得对应语言的消息，编辑器与 CLI 使用同一入口。可选的消息模板标识和参数用于本地化；未知宿主诊断使用原始 `message`，显示时仍执行长度上限。

```ts
import { compileLocal, formatLocalDiagnostic } from 'reactive-md';

const result = compileLocal(source);
for (const diagnostic of result.diagnostics) {
  console.log(diagnostic.code, formatLocalDiagnostic(diagnostic, 'zh'));
}
```

切换语言保留诊断码、严重程度和源码位置。同一 `0.x` minor 系列内，现有诊断码的含义保持稳定；可以新增诊断码，不能把旧码改用于另一类错误。删除、改名或改变含义须在新的 minor 版本中说明迁移。显示文案可以改进，机器判断应使用 `code` 和结构化字段。

`range` 使用从零开始的 UTF-16 索引，表示半开区间 `[start, end)`。`line` 和 `column` 从 1 开始，列按 UTF-16 代码单元计数。LF 换行使行号增加，CRLF 占两个源码代码单元。范围始终指向未经规范化的原始源码。

诊断数量达到上限时，新警告可以被省略；新的错误优先替换已有警告。编译错误使 `ok` 为 `false`。运行时写入被拒绝时，已提交状态与 revision 保持不变。

## 文本长度

| 用途 | 计数单位 |
| --- | --- |
| 源码偏移、诊断列号、源码与字符串资源预算 | UTF-16 代码单元，即 JavaScript `string.length` |
| 字符串的 `len()`、文本控件 `min-length` / `max-length` | Unicode 码点 |
| 数组的 `len()`、数组项数限制 | 元素个数 |

例如，`😀` 占 2 个 UTF-16 代码单元、1 个码点；`e` 加组合重音占 2 个码点；`👩‍💻` 占 5 个 UTF-16 代码单元、3 个码点。长度校验按码点，不合并字素簇，也不执行 Unicode 规范化。未配对的 UTF-16 代理项按一次字符串迭代计为 1。

编译器的初值校验、运行时写入校验和参考渲染器使用相同规则。独立的字符串资源预算先按 UTF-16 检查，邮箱的 254 上限也保持 UTF-16 计数。`countLocalCodePoints(value)` 提供与文本约束相同的计数。

文档预算统计原始源码；属性值在支持的 HTML 实体解码后计数。字符串拼接与插值还会检查结果长度。例如，属性中的 `&amp;` 在源码中占 5 个代码单元，解码后占 1 个。属性引号内的换行仍计入值的长度。

## 资源预算

长度上限均包含边界值，超过上限才拒绝。每次独立编译或求值从对应预算的起点重新累计；缓存命中仍须遵守该操作的输入和状态校验。

| 资源 | 上限与单位 | 累计范围 |
| --- | --- | --- |
| 文档源码 | 1,000,000 个 UTF-16 代码单元 | 每次编译的原始源码 |
| 语法节点 | 默认 10,000 个 | 每次解析期间累计构造，包含中间节点；宿主可按次配置 |
| 组件嵌套 | 100 层 | 当前组件解析调用链 |
| 标签名、属性名、绑定名 | 128 个 UTF-16 代码单元 | 每个名称 |
| 主题名称 | 64 个 UTF-16 代码单元 | 每个主题名称 |
| 字符串值、属性、模板 | 100,000 个 UTF-16 代码单元 | 每个值或模板，拼接输出也受限 |
| 数组 | 10,000 项 | 每个数组 |
| 数组成员字符串长度之和 | 100,000 个 UTF-16 代码单元 | 每个数组的所有字符串成员 |
| 邮箱地址 | 254 个 UTF-16 代码单元 | 每个非空邮箱值 |
| 编译诊断 | 100 条 | 每次编译，解析和编译阶段共同计数 |
| 单条诊断消息 | 2,000 个 UTF-16 代码单元 | 每条显示消息；超出部分截断 |
| 诊断模板参数 | 最多 16 个，单个字符串 256、全部值文本合计 2,000 个 UTF-16 代码单元 | 每条诊断的可序列化参数；超出部分截断或省略 |
| 表达式源码 | 4,000 个 UTF-16 代码单元 | 每个表达式 |
| 表达式 AST | 2,000 个节点 | 每个表达式的累计构造 |
| 表达式解析 / AST 深度 | 100 / 200 层 | 解析调用深度 / 最终 AST 深度 |
| 表达式求值 | 10,000 次节点访问、250 层深度 | 每次表达式求值；短路分支仅计实际访问 |
| LaTeX 源码 | 50,000 个 UTF-16 代码单元 | 每个公式 |
| LaTeX 记号 / AST | 20,000 个记号 / 5,000 个节点 | 每个公式解析，记号数含 EOF |
| LaTeX 解析 / 求值深度 | 120 / 1,000 层 | 对应调用链 |
| 独立 LaTeX 求值 | 默认 20,000 次节点访问 | 每次 `evaluate`；显式共享预算按传入预算累计 |
| 绘图曲线 | 16 条 | 每个 `<plot>` |
| 每条曲线采样 | 2 至 2,000 点 | 每次采样请求，端点计入 |
| 文档采样点总量 | 20,000 点 | 所有绘图的曲线数乘以请求采样数，包含隐藏区域 |
| 单条曲线计算 | `max(1,000,000, samples × 1024)` 次节点访问 | 一次 `samplePlot`，包含间断检测的额外求值 |
| 文档绘图计算 | 2,000,000 次节点访问 | 同一运行时 revision 内所有绘图采样；新 revision 重置 |

计算步数计 AST 求值节点访问，不是毫秒。独立调用 `samplePlot` 时，跨曲线的共享累计由调用者传入共享预算；参考渲染器为文档维护共享预算和采样缓存。

表达式编译缓存最多 500 项，公式编译缓存最多 512 项，每个运行时的表达式缓存最多 200 项。它们按条目管理内存，不改变输入是否合法；公式缓存满后清空再写入。缓存不会免除每次求值的计算预算。

## 验收

回归用例覆盖 Unicode 长度、UTF-16 定位、CRLF、预算临界值、双语诊断字段一致性，以及警告占满时的错误保留。编辑器和 CLI 的集成检查使用真实诊断对象；业务逻辑不依赖完整消息文本。版本兼容说明见[版本与兼容性](compatibility-ch.md)，命令行使用见[作者工具](author-tools-ch.md)。
