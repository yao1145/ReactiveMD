## 状态总览

### 已完成

| 项目 | 证据 |
| --- | --- |
| 独立单次编译入口 | `reactive-md/compiler` 与 `reactive-md/compiler/standard`，含包边界和独立消费者验证 |
| `strict` 与局部恢复 | RMD 文本降级、局部 HTML 修复，已贯通会话、Worker、补丁和导出 |
| 三仓库拆分 | 引擎、编辑器、Demo 独立维护，使用 tarball 和锁文件消费 |
| 组件运行时服务核心 | 身份、种子随机、调度器、组件状态协议与 React 钩子；见[组件运行时服务](component-runtime-services-ch.md) |
| 游戏示例迁移 | Tetris 使用 `useTicker`，2048 使用 `useSwipe`，Demo 已更新 |

### 部分完成

| 项目 | 待补 |
| --- | --- |
| 单次参考路径与阶段拆分 | 独立 runtime 入口和进一步 phase 拆分 |
| 独立包边界 | Lezer、GFM、parse5 等可选能力尚未完全拆出 |
| 组件运行时服务 | 导出 CLI 的组件状态 sidecar、游戏保存 UI、后台与触控浏览器验收、存储后端、尺寸测量和播报 |

- 主题语义 token、基础控件和窄屏/离线完善。
- 日常作者工具：VS Code、模板、保存和资源导入。
- 组件与主题目录。
- 1.0 稳定化和生态建设。
- 云端同步、多人协作、开放市场、更多渲染器和 AI 写作。

## 阅读入口

当前实施入口为[近期规划：编译内核、宽松恢复与仓库拆分](near-term-plan-ch.md)。该文档已合并原编译内核架构方案，并收拢原长期路线图；实施规则与阶段状态统一在其中维护。

| 阅读目的 | 近期规划中的位置 |
| --- | --- |
| 首次接手与源码定位 | 第 1 节：快速接手 |
| 编译器、编辑器、Demo 的职责 | 第 2 节：目标架构与仓库边界 |
| 编译配置与返回值 | 第 3 节：编译接口与结果契约 |
| strict、HTML 恢复与 RMD 文本降级 | 第 4 节：实现规则 |
| 增量、Worker 与状态保留 | 第 5 节：一致性规则 |
| 执行顺序与完成条件 | 第 6–8 节：路线图、验证与交接 |
| 主题、作者工具、目录和 1.0 | 第 9 节：后续方向与资料 |

近期按“固定基线 → 单次编译 → 局部恢复 → 执行与宿主一致 → 包边界 → Demo 迁仓 → 编辑器迁仓”推进。三仓库是目标维护形态，公开包消费验证是迁移前提。

长期继续围绕可嵌入的交互文档系统发展：共享语言语义、版本化组件与主题契约、完整作者工作流和可验证分发。原时间表由近期规划的阶段验收替代；后续能力按真实使用需求推进。

组件侧的运行时服务（身份、随机、调度、手势和状态保存）见[组件运行时服务](component-runtime-services-ch.md)。
